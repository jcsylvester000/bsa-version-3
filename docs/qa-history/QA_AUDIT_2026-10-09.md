# Part 2 — Data check and enhancements (2026-10-10)

Owner decisions: lease scoring stays (lower rent scores higher); run a data check; enhance.

## How the data was checked
- **Reference files** (`prisma/data/*.json`): ranges, duplicates, natural-key collisions, coordinates, truth layer,
  schedule years; plus `npm run db:validate`.
- **Live database** (read-only, as admin, through `/api/admin/data-stats`, `/api/admin/capture/coverage`,
  `/api/runs` and `/api/modules` for all 47 runs / 104 sites). Neon itself isn't reachable from the agency
  sandbox or the linked computer's shell, so the check used the app's own read APIs.

## Data findings

| ID | Severity | Finding (evidence) | Status |
|---|---|---|---|
| D1 | High | **Zonal "indicative rent" wildly off.** All 104 live lease rows used a *city-wide* zonal band (no site carried a barangay). Those bands span 12–240× (Taguig CR ₱9,000–₱2,160,000), so the midpoint was meaningless: indicative rent showed **₱10,845/sqm/mo for BGC** and ₱5,000 for Makati (comps: ₱1,500–₱4,000). | **[FIXED]** bands wider than 6× are reference-only (no cross-check, no zonal-derived rent; a plain note says why). Latest BIR schedule only (2025 rows win over 2019–2024 rows). Barangay resolved from the pin when boundaries are loaded. |
| D2 | High | **Accessibility pillar missing on every run** (`pillars_missing:accessibility` on all site-fit rows). Live POIs: 19,237 competitor vs **284 transport**; NCR transport layer was never ingested, and the back-fill treated NCR as "covered" (≥ 60 places of any kind). | **[FIXED in code]** a rich area with *no* transport / health / education places nearby is now "partial" and back-fills just those layers. **[OWNER]** run `npm run db:ingest:osm:transport` once for NCR. |
| D3 | High | **Asking rent lost on every re-run.** The pipeline always benchmarked lease with no rent; "Re-run analysis" and the new automatic refresh after a back-fill wiped the rent the user entered on the Lease tab (all 104 live lease rows have no score). | **[FIXED]** new `candidate_site.asking_rent_php_sqm` (migration `20261010000000_candidate_asking_rent`), optional asking-rent field per site at intake, Lease tab saves it to the site, re-runs reuse it and the user's corridor choice. |
| D4 | Medium | **Mall table empty live** (`mall_property` = 0; file has 33 malls) → the Mall module always reads "no data". | **[OWNER]** `npm run db:ingest -- malls`. |
| D5 | Medium | **NCR barangay tags at 5.5 %** (994 of 17,979 places); NCR had no PSGC mapping, so `db:fetch-boundaries` couldn't load it. | **[FIXED in code]** NCR + Davao PSGC mappings added. **[OWNER]** `npm run db:fetch-boundaries -- --region=ncr` then `npm run db:tag-boundaries`. |
| D6 | Low | `zonal.real.json`: 146 Quezon City barangay rows repeated (QC + Novaliches source files; 141 identical, 5 differ slightly) — the loader's upsert kept the last. | **[FIXED]** merged (2,317 → 2,171 rows, low = min, high = max); validator now warns on repeated natural keys. |
| D7 | Low | Demographics: two pairs of different barangays share one centroid (Catmon/NBBS Dagat-dagatan; Wack-Wack/Highway Hills). ## Enhancements
- **Rent vs. location line** in the Lease summary (screen + PDF), e.g. "Rent sits above the corridor median and the
  location reads strong … this site's pull may justify a larger share of the rent budget — the broker and client
  decide." Positional only; checked against the shared price-verdict patterns.
- **Asking rent at intake** (optional, per site), kept across re-runs; Lease tab prefilled with it.
- **Provisional marker (F1)** in the Final Report hero and PDF while place data is being gathered.
- **Zonal bands**: latest schedule only, reference-only when too wide, barangay from the pin.
- **Back-fill**: fills missing transport/health/education even in busy areas.
